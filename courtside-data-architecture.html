Objective

Turn the unstructured HTML of basketball-reference.com into clean, typed, validated Python data — without getting blocked. A declarative TableEndpoint registry drives everything from CLI subcommands to URL templates, table-extraction strategy, CSV column contracts, and Pydantic row models.

Value Delivered

  • One import → typed NBA data (totals, advanced, play-by-play, box scores, drafts, standings, awards, schedules, contracts).
  • Anti-blocking via curl-cffi TLS impersonation + process-wide rate pacing + persisted 429 "jail".
  • Trust via row-level Pydantic validation with schema-drift detection.
  • Flexibility: JSON, CSV, or DataFrame output from one call.

Target Users

  • Data analysts & sports researchers
  • NBA bloggers & journalists
  • Fantasy / betting model builders
  • Developers embedding stats in apps

Success Metrics

  • Endpoint coverage breadth (55 of BR's pages)
  • Zero 429 escalations under recommended pacing
  • Schema-drift caught before bad data ships
  • Sub-second cached re-fetch latency

Lineage

Derived from Jae Bradley's basketball_reference_web_scraper. Independently extends it with a declarative registry, generic table pipeline, Pydantic validation layer, and an opt-in debug-trace subsystem. The Strangler-Fig migration of the inherited page-object parser stack is complete — that stack has been fully removed; "legacy" in the codebase now names only the runtime validation fallback in client/_pipelines/legacy.py, selected per-endpoint when row_model is None.

3Processing Pipeline

Five staged transformations turn a user's typed kwargs into validated rows. Each stage is observable via the debug trace when debug=True.

Table-Resolution Fallback Chain (Stage ③)

The registry declares where each endpoint's data lives. Resolution tries, in order:

table_id  →  fallback_table_ids  →  commented_table_id  →  first <table>  →  transaction_list_fallback

This single declarative chain eliminates dozens of bespoke page-object methods and is what powers the generic path for non-custom endpoints.

TableEndpoint Spec Anatomy — endpoints.py (frozen, slots-only dataclass, 18 fields)

Each of the 55 registry entries is one immutable spec. CLI subcommand flags, client function signatures, URL rendering, table lookup, CSV headers, the validation branch, and HTTP-status → error mapping all derive from these fields.

value_columnboolRenames rightmost stat col → value (leaders pages)

Three factory helpers reduce boilerplate: _season (defaults error=InvalidSeason, min_year=1947), _team (InvalidTeam), _player (InvalidPlayer). error_mappings(params) builds the per-call {status: factory} dict via dict.fromkeys(error_status_codes, factory).

4System Architecture — Layered View

🎯 Public API & CLI Layer
cli.py (argparse tree, one subcommand per registry entry) · __main__.py (python -m courtside_data) · client/ (typed per-domain functions: draft, games, league, players, playoffs, teams) · CourtsideClient (ContextVar-injecting proxy) · client/_runner.py (dispatcher: registry lookup, service resolution, error mapping, dual validation, output dispatch)
⚙️ Fetch & Parse Layer
http_service.py — rate-limited, jailed, TLS-impersonating transport with stamina retries + hishel caching + bounded selector cache · parsing/generic.py (GenericTable, GenericEndpointHandler) · parsing/custom.py (CustomEndpointHandler for standings, play-by-play, box scores, search, awards, schedules, friv) · parsing/tables.py (commented-table extraction), rows.py, cells.py · parsing/_selectolax_backend.py (Lexbor fast path, cross-validated against lxml)
🛡️ Validation & Schema Layer
schemas/ — Pydantic v2 BRRow base (extra="ignore") + stat-block mixins, ~20 Annotated BeforeValidators in _fields.py, ROW_ADAPTERS populated at import time · client/_pipelines/pydantic.py (modern path) vs legacy.py (coerce+validate fallback) · output/field_types.py + type_validator.py (heuristic column-type coercion)
📤 Output & Serialization Layer
output/service.py (strategy-pattern OutputService) · output/writers.py (JSONWriter · CSVWriter · DataFrameWriter) · output/fields.py (chain-of-responsibility value formatters) · output/columns/ (52 named *_COLUMN_NAMES lists across 9 domain modules — the CSV contract)
📦 Declarative Registry & Cross-Cutting
endpoints.py — the single source of truth: ENDPOINTS dict of ~55 TableEndpoint specs (URL template, table strategy, CSV columns, Pydantic row model, projection, error mappings). CLI subcommands and client signatures derive from it. · data.py (domain enums), errors.py (taxonomy), utilities.py
🔮 Observability + Validation Fallback (opt-in / per-endpoint)
Validation fallback — client/_pipelines/legacy.py (validate_rows_legacy: output.field_types.coerce_data + output.type_validator.validate_rows), branched on endpoint.row_model is None. The modern Pydantic path is client/_pipelines/pydantic.py. Both pipelines return the same (data, csv_column_names) contract. · Observability — debug/: opt-in DebugConfig, bounded DebugTrace collector, ContextVar ambient context, OTel-inspired spans, artifact redaction, best-effort disk sink, probe.py all-endpoint runner, schema.json v3 envelope. Note: the inherited page-object parser stack (the old *Page → *Table → *Row hierarchy) has been fully removed — there is no legacy/ subpackage.

Concurrency Model — 4 State Scopes

ScopeState & Guard
Process-wide
all sessions		HTTPService._last_request_time, _jailed_until, _jail_state_loaded (all ClassVar) guarded by ClassVar[threading.RLock]. Jail survives restarts via jail.json.
Module singleton_runner._shared_service — lazily created under _shared_service_lock (double-checked locking). Reuses HTTP connections, response cache, parser graph.
Per-call
ContextVar		_runner._service_override — set by CourtsideClient for the duration of one method call (try/finally reset).
Per-instanceHTTPService._selector_cache — instance-owned TTLCache.

Consequence: rate-limit pacing is global — two CourtsideClient instances with different cache/headers/impersonate still serialize through one _rate_limit_lock. Pacing is not a per-client constructor knob.

Caching Layers — 3 Distinct Scopes

LayerMechanism & Bounds
HTTP responsehishel.SyncCacheTransport wrapping the curl transport (RFC 9111, SQLite-backed). On by default in HTTPService (cache=True); keyed by URL; freshness server-driven.
Selector cachecachetools.TTLCache[str, parsel.Selector] — maxsize=16, ttl=600s. Evicts on age and size. Keyed by URL.
Jail persistenceSingle {"jailed_until_epoch"} JSON blob via orjson under platformdirs.user_cache_dir(...)/jail.json. Cross-restart.

The selector cache is what makes the multi-table-same-page pattern cheap — e.g. the three friv_7_game_playoff_series_outcomes_* endpoints share one fetch and one parse.

Stat-block mixins composed onto BRRow subclasses: BasicBoxScoreStats, TotalStats, PerGameStats.

Resilience Constants — verified from http_service.py

6.0 sRate-Limit Interval (10 req/min ceiling)
1.0 sPacing Jitter (uniform 0–1, ~8.6 req/min avg)
300 sJail Threshold (5 min) → no retry, persist jail
60 sMax Retry-After Wait (capped pre-stamina)
3Retry Attempts (stamina attempts)
1→10 sBackoff (wait_initial=1, wait_max=10, jitter=0.5)
30 sHTTP Timeout (10 s connect)
429,502–504Retryable Status (others abort)

Overrides: BASKETBALL_REF_RATE_LIMIT_INTERVAL, BASKETBALL_REF_RATE_LIMIT_JITTER, BASKETBALL_REF_MAX_RETRY_AFTER. Stamina's wait_max does not bind hook-returned waits — the 60 s cap is applied inside the _should_retry predicate before the float reaches stamina.

Reliability & Resilience State Machine

How the transport reacts under load — the same logic every endpoint reuses:

request → _apply_rate_limiting ─┬─ jailed_until > now? ───▶ raise RateLimitJailed
                                  └─ pace: wait since _last_request_time
         ↓
         _get ──▶ HTTP 429?
                   ├─ Retry-After > 300s? ──▶ set _jailed_until, persist, raise RateLimitJailed
                   └─ else ──▶ _should_retry returns min(Retry-After, 60s)
                                → stamina.retry_context sleeps that exact float
         ↓
         HTTP 5xx / TransportError? ──▶ _should_retry → True → stamina backoff
         ↓
         HTTP 404 / 500 (domain-mapped)? ──▶ endpoint.error_mappings → InvalidSeason / InvalidTeam / ...
         ↓
         200 ──▶ parsel selector (cache hit?) ──▶ return

Error Taxonomy — courtside_data/errors.py (9 domain exceptions + base)

Catch CourtsideDataError to scope any library failure without swallowing httpx transport errors. RateLimitJailed propagates naturally — it is not an httpx.HTTPStatusError, so _call_with_error_mapping does not intercept it.

CourtsideDataError                              (base)
├── InvalidDate(day, month, year)               ← player_box_scores / team_box_scores / play_by_play
├── InvalidSeason(season_end_year)              ← _season() factory default
├── InvalidTeam(team_abbreviation)              ← _team() factory default
├── InvalidPlayer(player_identifier)            ← _player() factory default
├── InvalidPlayerAndSeason(player_id, season)   ← gamelog endpoints (status 404 or 500)
├── InvalidSearch(term)                         ← search endpoint
├── RateLimitJailed(retry_after)                ← HTTPService (Retry-After > 300s; not an HTTPStatusError)
├── MissingPlayerSlug(endpoint, row_idx, player)← CustomEndpointHandler (data-append-csv absent)
└── SchemaDriftError(endpoint, url, pydantic_err)← Pydantic pipeline (row_model total validation failure)
